# 캡스톤 최종보고서 기본 양식

이 양식은 앞으로 작성할 캡스톤 **최종보고서**의 기본 양식이다.
과거 주간보고서와 중간보고서 파일은 historical snapshot 으로만 유지한다.
최종보고서 작성 규약의 current truth 는 [[/03-conventions/conv-final-report-writing.md]] 이다.

본문 구성은 보고서 작성 시점의 완성도와 제출 요구에 맞게 바뀔 수 있지만, 교수님 기준과 구현 완성도 중심 방향은 유지한다.
보고서 산출물에는 차례/목차 페이지를 넣지 않는다. 작성 완료 후 사용자가 한글에서 차례를 직접 입력하거나 생성해야 한다고 안내한다.
문서 산출물은 HWP만 생성한다. HWPX는 생성하지 않는다.
화면 캡처는 실제 서비스 DOM redbox 또는 `원본 이미지 + HTML overlay harness` 방식으로 다시 캡처한 PNG만 사용한다.

# 2. 이번 주 진행사항 및 전체 완성도 자체평가

이 섹션은 표지와 초록 / 요약 바로 뒤, 본문 앞에 둔다.
주간보고서 대체물이 아니라 최종보고서 앞부분에서 현재 진행 상태와 남은 보강 항목을 빠르게 보여주는 선행 섹션이다.

## 2.1 이번 주 진행사항

- KST 기준 직전 월요일 09:00부터 기준 시각까지의 변경사항
- 모든 시간은 `YYYY-MM-DD HH:MM KST` 형식으로 표기하고 offset 표기는 생략
- 모든 레포의 `main`으로 merge된 PR branch 기준 변경사항
- PR merge 시각이 보고 기간 안이면 해당 PR의 첫 commit 시각부터 merge 시각까지를 개발 기간으로 산정
- 먼저 자연어로 이번 주에 만든 기능, 고친 문제, 사용자에게 보이는 변화, 검증 근거를 설명
- 그 다음 기능/문제 중심 상세 표를 작성하고, PR 목록은 마지막 추적 근거 표로 배치
- 완료 / 진행 중 / 보강 필요 항목 구분

# 2파일 최종 산출물 원칙

최종 제출/검토자가 실제로 읽어야 하는 파일은 다음 두 개로 고정한다.

1. `docs/08-reports/99-combined-report.md` — 보고서
2. `docs/08-reports/99-combined-report-appendix.md` — 부록

다른 보고서 조각, 과거 부록, architecture/status/convention 문서는 작성 근거로만 사용한다. 최종 독자는 위 두 파일만 열어도 프로젝트 목표, 설계, 구현, 화면 흐름, 코드, DB/ERD, 검증, 한계를 이해할 수 있어야 한다.

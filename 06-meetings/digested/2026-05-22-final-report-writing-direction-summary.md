# 회의 목적

교수님이 제시한 최종보고서 평가 기준에 맞춰 앞으로의 보고서 작성 구조와 변경사항 산정 기준을 확정한다.

# 핵심 결정

- 앞으로 주간보고서는 새로 작성하지 않고 최종보고서만 작성한다.
- 최종보고서 목차 바로 뒤에는 `이번 주 진행사항 및 전체 완성도 자체평가`를 둔다.
- 최종보고서의 1순위 논리축은 구현 완성도 중심으로 둔다.
- 구현 완성도는 기능별 종합 증거 매트릭스로 입증한다.
- 목차는 보고서 작성 시점에 맞게 바뀔 수 있지만, 교수님 기준과 구현 완성도 중심 방향은 유지한다.
- 매주 변경사항 기준은 KST 기준 직전 월요일 09:00부터 보고서 작성 현재 시각까지로 한다.
- 변경사항과 현재 상태는 모든 레포의 `main` 브랜치를 기준으로 작성한다.

# 새 요구사항

- 최종보고서에는 교수님 기준의 서론, 관련 연구/기술, 시스템 설계, 구현, 실험 및 결과, 결론, 참고문헌 구조가 반영되어야 한다.
- 이번 주 진행사항 섹션은 단순 주간보고서가 아니라 최종보고서 앞부분의 진행 현황 및 완성도 자체평가로 작성한다.
- 기능별 완료도는 화면, API, DB, 테스트, 한계 근거를 함께 제시해야 한다.

# 새 규약

- 보고서 작성 기준은 `[[/03-conventions/conv-final-report-writing.md]]` 를 current truth 로 사용한다.
- `08-reports` 의 주간보고서 파일은 과거 snapshot 으로만 유지하고, 새 보고서는 최종보고서 형식으로 작성한다.

# 구조 / 아키텍처 변화

- 코드 구조 변화는 없다.
- 문서 구조상 `08-reports` 는 최종보고서 중심으로 해석한다.

# 리스크

- 모든 레포의 `main` 기준을 확인하지 않으면 보고서가 로컬 작업 상태나 특정 브랜치 상태를 잘못 반영할 수 있다.
- 구현 완성도 중심으로 작성할 때 한계점을 숨기면 교수님 기준의 객관적 근거와 문서 완성도가 약해질 수 있다.

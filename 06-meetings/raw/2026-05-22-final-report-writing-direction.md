# 원문

교수님이 제시한 최종보고서 기준에 맞춰 보고서를 다시 작성한다.
앞으로는 주간보고서를 더 이상 작성하지 않고, 최종보고서만을 대상으로 작성한다.
단, 최종보고서 형식의 목차 바로 뒤에는 이번 주 진행사항을 작성한다.

교수님 기준의 큰 항목은 다음과 같다.

- 서론
  - 연구 배경
  - 필요성
  - 목적
- 관련 연구 / 기술
  - 기존 방법 조사
  - 차별성 분석
- 시스템 설계
  - 구조
  - 알고리즘
  - DB 설계
  - UML 등
- 구현
  - 사용 기술
  - 개발 환경
  - 코드 구조
- 실험 및 결과
  - 테스트 방법
  - 성능 평가
  - 한계점
- 결론
  - 성과
  - 개선 방향
- 참고문헌

보고서에서 중요한 것은 다음과 같다.

- 논리성
- 자세한 기술 설명
- 객관적 근거
- 표 / 그림 캡션
- 참고문헌 형식

평가 포인트는 다음과 같다.

- 실제로 얼마나 깊게 수행했는가
- 기술 이해도
- 문제 해결 과정
- 문서 완성도

# 추가 확정 사항

- 보고서의 1순위 논리축은 구현 완성도 중심으로 둔다.
- 구현 완성도는 단순 기능 나열이 아니라 기능별 종합 증거 매트릭스로 입증한다.
- 기능별 종합 증거 매트릭스는 화면, API, DB, 테스트, 한계를 함께 묶어 완료도를 평가한다.
- 목차는 매 보고서마다 변경될 수 있지만, 교수님 기준과 구현 완성도 중심의 큰 방향성은 유지한다.
- 목차 바로 뒤에는 이번 주 진행사항과 전체 프로젝트 완성도 자체평가를 함께 둔다.
- 매주 변경사항 기준은 KST 기준 직전 월요일 09:00부터 보고서 작성 현재 시각까지로 한다.
- 변경사항과 현재 상태는 모든 레포의 `main` 브랜치를 기준으로 작성한다.

# 비범위

다음 항목은 완료 성과로 표현하지 않고 한계점 또는 개선 방향으로 분리한다.

- 실운영 / 상용 배포 완료
- 장기 현장 검증 완료
- 학사시스템 정식 연동
- 네이티브 모바일 앱 구현
